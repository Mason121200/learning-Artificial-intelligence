把这组概念串起来，可以形成一个从“概念 → 执行单位 → 调度模型 → 任务类型”的完整脉络：

**1. 并发 vs 并行**

- **并发（Concurrency）**：多个任务在时间上重叠推进，单核也可，靠切换/调度实现。
- **并行（Parallelism）**：多个任务在同一时刻真正同时执行，需要多个执行单元（多核/多处理器）。
- 关系：并行是并发的一种特殊形式；并发不要求多核，并行要求多执行单元。

**2. 进程 vs 线程**

- **进程（Process）**：操作系统进行资源分配、隔离与保护的基本单位，拥有独立的虚拟地址空间。
- **线程（Thread）**：进程内的调度单位，与同进程其他线程共享地址空间；内核级线程通常由 OS 抢占式调度，用户态线程/协程可能由运行时协作式调度。
- 关系：进程提供隔离，线程提供并发/并行的执行载体。

**3. 事件循环与协程**

- **事件循环（Event Loop）**：异步运行时的核心调度器，通常运行在单线程内，通过 I/O 多路复用等待就绪事件，再恢复对应协程或回调。
- **协程（Coroutine）**：用户态轻量执行单位，由事件循环调度，遇到 `await` 让出控制权。
- 关键：事件循环不怕 I/O 等待，但怕阻塞调用和 CPU 密集任务。

**4. 阻塞**

- **阻塞（Blocking）**：调用返回前，当前执行流无法继续推进；执行单元被挂起等待，通常让出 CPU，但无法同时处理其他工作。
- 阻塞 ≠ 忙等待：阻塞让出 CPU，忙等待持续消耗 CPU。
- 影响：单线程事件循环一旦阻塞，整个循环停摆。

**5. I/O 密集 vs CPU 密集**

| 类型 | 瓶颈 | 适合手段 | 单核能否改善 |
|---|---|---|---|
| I/O 密集 | 等待 I/O | 并发（异步/多线程/多进程） | 能，靠重叠等待 |
| CPU 密集 | CPU 计算 | 并行（多进程/多核/GPU） | 不能，必须多执行单元 |

**6. 一张总图**

```text
并发：单核也能重叠推进
  ├── I/O 密集 → 事件循环 / 协程 / 多线程
  └── CPU 密集 → 需要并行 → 多进程 / 多核 / GPU

并行：多执行单元真正同时执行

执行单位：
  进程：资源分配 + 隔离 + 独立虚拟地址空间
  线程：调度单位 + 共享进程地址空间
  协程：用户态轻量单位 + 由事件循环调度

调度模型：
  事件循环：单线程内驱动协程/回调，等 I/O 就绪再恢复
  阻塞：卡住当前执行流，通常让出 CPU
```

**7. 一句话总总结**

> **并发是单核也能做的“重叠推进”，并行是多执行单元才能做的“真正同时执行”；进程管资源和隔离，线程管调度，协程由事件循环驱动；I/O 密集靠并发重叠等待，CPU 密集靠并行真正同时算。**

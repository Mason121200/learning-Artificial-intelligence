# LLM API（API 调用的基础实践）


## 一、API 调用

经过基础理论学习并了解API调用的请求体和响应体结构后，很自然的就能意识到要实现对话功能只需通过API调用即可实现，不过在实现这个功能前，需要提前准备好可以提供服务的base_url、model、API_key等参数，可以到提供LLM API服务的厂商官网中申请Key，并查看对应的url、model参数。 最简单的API调用程序，由三部分组成：

**1.** 创建 OpenAI 客户端对象，（base_url 和 api_key 是它的构造入参，之后调用 client 时复用）
```python
from openai import OpenAI

client = OpenAI(base_url="https://api.deepseek.com", api_key="YOUR_API_KEY")
```

**2.** 组装并发起API调用请求，这里构建的就是理论学习中提到的请求体，所以必须要保证结构相同，否则服务端参数校验会报错，LLM无法处理请求。
```python
response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {"role": "system", "content": "你是一个AI助手，当用户问你问题时，请为用户提供可靠的回答，禁止编造。"},
        {"role": "user", "content": "你好"},
    ],
)
```

**3.** 打印响应内容，这里取出的数据，就是理论学习中提到的响应体的内容，response是整个响应体，数据在响应体内被choices[0]、message、content逐层包裹，逐层定位最终获取到回复数据并打印。
```python
print(response.choices[0].message.content)
```

完成这几步，一个简单的API调用程序就完成了，但这个程序只能进行一次调用，调用并打印结果后就会退出程序，想要连续对话的话，就需要添加上循环。为方便讲解，后文中如url、key以及相关参数我直接使用关键字代替。

## 二、连续对话的 API 调用程序

要实现连续对话的bot程序，需要考虑用户动态输入、历史记录的保存和重组，同时要保留退出条件，避免程序死循环。由于API的调用是一个重复动作，所以可以考虑使用OOP编程思维将API调用封装为一个类模块，实现反复调用。
**1.** ChatServer类的编写： 
此处我将模型的url、key、model作为创建ChatServer实例的参数，调用时通过这三个参数能实现对厂商和模型进行更换，这意味着再调用其他模型时我只需要重新创建一个对象即可，无需重新编写代码，这两
个对象可以同时存在且互不干扰，OOP的魅力在此已经有所体现了。
```python
from openai import OpenAI


class ChatServer:
    PROMPT = "你是一个AI助手，当用户问你问题时，请为用户提供可靠的回答，禁止编造。"

    def __init__(self, base_url, api_key, model):
        self.client = OpenAI(base_url=base_url, api_key=api_key)
        self.model = model
        self.history = []

    def chat_create(self, message):
        # 1. 先把用户消息存进历史（发给模型的就是这份历史）
        self.history.append({"role": "user", "content": message})

        # 2. 组装请求并调用
        messages = [{"role": "system", "content": self.PROMPT}] + self.history
        response = self.client.chat.completions.create(model=self.model, messages=messages)
        content = response.choices[0].message.content

        # 3. 模型的回复也要存进历史，下一轮才接得上
        self.history.append({"role": "assistant", "content": content})
        return content
```

在这个类中，由于需求简单，所以我将提示词定义为了类属性，以保证每个实例对象都使用这一套提示词。同时定义了三个实例属性，client是将OpenAI类实例赋值为ChatServer的实例属性，同时也说
明ChatServer依赖OpenAI SDK。这里的重点是交互数据的保存、组装，由于在实践中交互数据都是储存在列表变量history中，所以在代码中实际上进行的就是列表的操作。但需要注意，history中保
存的数据格式必须严格遵照请求体中的messages的格式储存。

**2.** 主循环调用：通过循环嵌套，实现了简单的会话选择和连续对话功能。定义了一个变量sessions字典用来存放会话实例对象，外循环实现会话选择功能，内嵌循环实现连续对话功能，两个循环
都通过input获取用户键盘输入并执行，用户退出需要输入exit实现跳出循环。
```python
from chat_server import ChatServer
sessions = {}
while True:
    chat_name = input("请选择你的对话>")
    if chat_name == "exit":
        break

    if chat_name not in sessions:
        sessions[chat_name] = ChatServer(base_url, api_key, model)
        
    chat = sessions[chat_name]
    while True:
        message = input("请输入并开始交流>")
        if message == "exit":
            break
        content = chat.chat_create(message)
        print(content)
```

在这个例子中，我编写了一个简单的chat bot程序，实现了简单的会话选择、连续会话和对话隔离的效果，但还存在着许多问题，如对话不中断，messages就会不断增加，直到超过上下文窗口。这是因为当前的程序没有对
chat bot的历史记录做裁剪，而是简单的累加，所以接下来需要为这个程序添加一个摘要功能。

## 三、配置参数设置

在开发过程中，参数的数据会越来越多，所以为了方便后续的编写以及敏感信息的保护，应该在项目根目录下建一个.env，将key等参数与代码分开存放，而不是明文编写在代码中。
**1.** 将代码参数写入.env文件。
```ini

LLM_COMPLETION=4.5

```

通过这种方式可以将这些参数统一到env配置文件中管理，避免明文写入代码程序，即实现了参数的统一管理，后续也可以继续根据需求拓展。

**2.** 创建文件config.py来封装环境变量参数。
```python
import os
from dataclasses import dataclass
from dotenv import load_dotenv

#@dataclass表示该类型为样板，仅需字段名和数据类型即可完成类型定义。frozen=True使得Config实例具备只读属性，创建后字段不可再更改。
@dataclass(frozen=True)
class Config:
    url: str
    model: str
    api_key: str
    system_prompt: str
    llm_cache: float
    llm_completion: float
    llm_miss: float
    summary_prompt: str
    max_content: int
    keep_content: int

#创建load_config方法，通过调用可以获取环境配置文件的内容，当env_file=None时，load_dotenv()默认将.env文件加载到环境变量中。不为None时，则加载指定文件。
def load_config(env_file: str | None = None) -> Config:
    load_dotenv(env_file)
    return Config(
        url=os.getenv("LLM_URL", ""),
        model=os.getenv("LLM_MODEL", ""),
        api_key=os.getenv("LLM_API_KEY", ""),
        llm_cache=float(os.getenv("LLM_CACHE", "0.05")),
        llm_completion=float(os.getenv("LLM_COMPLETION", "4.5")),
        llm_miss=float(os.getenv("LLM_MISS", "1.5")),
        system_prompt=os.getenv("SYSTEM_PROMPT", "你是一个AI助手，当用户问你问题时，请为用户提供可靠的回答，禁止编造。"),
        summary_prompt=os.getenv("SUMMARY_PROMPT", "简化用户信息，用简短的方式进行简要，保留语义压缩字数，你的输出将作为后续交互的历史摘要信息"),
        max_content=int(os.getenv("MAX_CONTENT", "10")),
        keep_content=int(os.getenv("KEEP_CONTENT", "3")),
    )
```

这些参数内容可以根据实际开发进行增减，因此后续不再重复提及，如有新的参数出现在Config类中，需到此进行添加。os.getenv("MAX_CONTENT","10")中的10是配置的默认值，当env中没有
这个参数时就会使用默认值代替，当env中有这个参数时，以实际值为准。

## 四、chat bot 历史摘要功能的具体实现

功能开发之前，需要考虑摘要触发的条件、保留数据的裁剪、历史数据清空和拼接以及存在两套提示词的情况，因此创建ChatServer实例对象需要的参数会增加，具体内容如上所述。

### 1.ChatServer类的改造

在ChatServer的改造中，由于会使用两套提示词，因此在实际实现过程中，不只是添加新的方法(history_reorganize)，还要重新调整编排方法(chat_create)，将response这一块的内容拆分出
来作为单独的方法来实现，这样就把提示词做成了入参（system_prompt），从而能实现两套提示词的替换。关于当前实现的历史摘要功能，是比较简单的实现方法，并没有考虑数据持久化、数据保存等问题，所以在实际生产环境
中，需要更完善的实现方法来实现。

```python
from openai import OpenAI
from config import Config


class ChatServer:
    def __init__(self, cfg: Config):
        self.client = OpenAI(base_url=cfg.url, api_key=cfg.api_key)
        self.model = cfg.model
        self.system_prompt = cfg.system_prompt
        self.summary_prompt = cfg.summary_prompt
        self.max_content = cfg.max_content
        self.keep_content = cfg.keep_content
        self.history = []

    def response_create(self, system_prompt: str):
        # 通用请求：prompt 由调用方给（正常对话 / 摘要，各一套提示词）
        messages = [{"role": "system", "content": system_prompt}] + self.history
        response = self.client.chat.completions.create(model=self.model, messages=messages)
        return response.choices[0].message.content

    def history_reorganize(self):
        limit = self.max_content * 2      # 触发的条数上限
        keep = self.keep_content * 2      # 要保留的条数
        if len(self.history) >= limit:
            history_cope = []
            for i in self.history[-keep:]:            # 先取出要保留的
                history_cope.append(i)
            for i in range(len(history_cope)):        # 再从历史里删掉
                self.history.pop()
            summary = self.response_create(self.summary_prompt)   # 对剩下的旧历史做摘要
            self.history = []
            self.history.append({"role": "system", "content": "历史摘要：" + summary})
            self.history += history_cope

    def chat_create(self, message: str):
        self.history_reorganize()                    # 先判断是否需要摘要
        self.history.append({"role": "user", "content": message})
        content = self.response_create(self.system_prompt)
        self.history.append({"role": "assistant", "content": content})
        return content
```

## 五、chat bot 用量统计功能的实现

用量统计功能要基于LLM返回的usage字段实现，根据LLM返回的响应可以获取到用量数据，通过对用量数据进行计算处理，可以实现简单用量监控。此处同样是以OOP思想实现的功能开发，将用量统计功能抽象为一个类，
基于功能实现的角度分析，将总用量amount_tokens、总成本amount_price、总命中amount_cache、总提示词amount_prompt以及模型的命中价格cache_price、未命中价格miss_price、输
出价格completion_price作为实例属性，设计了相对完整的功能方法——命中率、价格、累计等，完整的设计如下：

### 1.创建UsageTokens类

```python
from dataclasses import dataclass


@dataclass
class OncePrice:
    price: float
    tokens: int
    prompt: int
    hit_rate: float


@dataclass
class TotalPrice:
    price: float
    tokens: int
    hit_rate: float


class UsageTokens:
    def __init__(self, cache_price,miss_price,completion_price):
        self.amount_cache = self.amount_tokens = self.amount_prompt = self.amount_price = 0
        self.cache_price = cache_price
        self.miss_price = miss_price
        self.completion_price = completion_price

    def usage_create(self, response):
        """获取usage用量数据"""
        usage = response.usage
        self.cache = usage.prompt_cache_hit_tokens
        self.tokens = usage.total_tokens
        self.prompt = usage.prompt_tokens
        self.miss = usage.prompt_cache_miss_tokens
        self.completion = self.tokens - self.prompt

    def record(self, price):
        """累计方法，用于累计每次调用的数据"""
        self.amount_cache += self.cache
        self.amount_tokens += self.tokens
        self.amount_prompt += self.prompt
        self.amount_price += price

    def price(self):
        """价格计算"""
        price = float(self.cache * self.cache_price + self.miss * self.miss_price
                      + self.completion * self.completion_price) / 1000000      #模型价格以百万为单位，除以百万后计价单位才是真实的价格
        return price

    def hit_rate(self, cache, prompt):
        """命中率计算"""
        return cache / prompt * 100

    def once_price(self):
        """单次用量成本数据获取"""
        price = self.price()
        hit_rate = self.hit_rate(cache=self.cache, prompt=self.prompt)
        return OncePrice(price=price, hit_rate=hit_rate, tokens=self.tokens, prompt=self.prompt)

    def total_price(self):
        """总用量成本数据获取"""
        hit_rate = self.hit_rate(cache=self.amount_cache, prompt=self.amount_prompt)
        return TotalPrice(price=self.amount_price, tokens=self.amount_tokens,
                         hit_rate=hit_rate)
```

### 2.改造ChatServer类

基于功能的实现，需要对ChatServer进一步改造以适配当前的开发需求，因此，需要添加新的方法和实例属性，具体改造如下。

```python
from dataclasses import dataclass
from openai import OpenAI
from config import Config
from usage import UsageTokens, OncePrice, TotalPrice

#新增数据类
@dataclass
class UsageRep:
    once: OncePrice
    total: TotalPrice

#新增数据类
@dataclass
class Response:
    assistant: str
    usage_rep: UsageRep


class ChatServer:
    def __init__(self, cfg: Config):
        self.client = OpenAI(base_url=cfg.url, api_key=cfg.api_key)
        self.model = cfg.model
        self.system_prompt = cfg.system_prompt
        self.summary_prompt = cfg.summary_prompt
        self.max_content = cfg.max_content
        self.keep_content = cfg.keep_content
        self.history = []
        #新增实例属性，创建UsageTokens实例对象
        self.usage = UsageTokens(cache_price=cfg.llm_cache,completion_price = cfg.llm_completion,miss_price = cfg.llm_miss)
    
    #新方法
    def usage_price(self, response):
        """获取用量数据，累计并返回用量数据"""
        self.usage.usage_create(response=response)
        once=self.usage.once_price()
        price = once.price
        self.usage.record(price)                 # 记账
        total=self.usage.total_price()
        return UsageRep(once=once,total=total)

    def response_create(self, system_prompt: str):
        """组装消息并发起请求，返回最终回复以及用量数据"""
        messages = [{"role": "system", "content": system_prompt}] + self.history
        response = self.client.chat.completions.create(model=self.model, messages=messages)
        content = response.choices[0].message.content
        return Response(assistant=content, usage_rep=self.usage_price(response))

    def save_history(self, role, message):
        """保存历史记录"""
        self.history.append({"role": role, "content": message})

    def chat_create(self, message: str):
        """编排方法流程，返回最终回复"""
        self.history_reorganize()
        self.save_history(role="user", message=message)
        content = self.response_create(self.system_prompt)
        self.save_history(role="assistant", message=content.assistant)
        return content

    def history_reorganize(self):
        """历史记录裁剪、摘要"""
        limit = self.max_content * 2
        keep = self.keep_content * 2
        if len(self.history) >= limit:
            history_cope = []
            for i in self.history[-keep:]:
                history_cope.append(i)
            for i in range(len(history_cope)):
                self.history.pop()              #将保留轮次剔除，不进入摘要
            summary_rep = self.response_create(self.summary_prompt)
            self.history = []
            self.history.append({"role": "system", "content": "历史摘要：" + summary_rep.assistant})
            self.history += history_cope
```

    while True:
